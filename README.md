# 予約・顧客管理システム

予約制サービス業（個人サロン）向けの、予約・顧客管理システムです。techmeets Week22〜24 の総合演習として、個人で開発しています。

紙や LINE に分かれていた「予約」「顧客情報」「施術の記録」「来店前の連絡」を、1つの管理画面にまとめることを目指しました。お客様は、空き状況を見てオンラインで予約でき（はじめての方はその場で登録、登録済みの方はかんたんログイン）、自分の利用履歴も確認できます。

## 主な機能

### 管理者向け

- **ダッシュボード**：明日・今後7日間の予約件数、顧客数、本日の予約、リマインドの送信状況（送信済み／未送信／メール未登録）。
- **顧客管理**：氏名・電話番号（ハイフンの有無を問わない）・カルテ番号での検索。カルテ番号は「生年月日の月日4桁-連番」（例：`0202-1`）で、同じ誕生日の人とも重ならない。一度付けた番号は変えず、削除した人の番号も使い回さない。詳細画面に、対応記録・予約履歴・事前カウンセリング・AI提案結果をまとめて表示。
- **CSV取り込み**：既存ソフトから出力した顧客CSVを、プレビューで確認してから登録。文字コード（UTF-8／Shift_JIS）を自動判別、電話番号・生年月日を整形、重複（同じ電話番号）と不備のある行は取り込まず理由を表示。
- **予約管理・予約表**：メニューの所要時間を使った重複チェック。予約表は週・2週間の切り替えができ、予約を時間の長さに合わせて表示。空いている時間（営業時間内・30分ごと）を押すと、その日時で予約を登録できる。管理画面で予約の日時を変えると、お客様に変更のお知らせをメールで送り、リマインドを未送信に戻す（新しい日時の前日に、もう一度送る）。
- **対応記録**：施術内容・カウンセリングシート（お悩みのチェック項目と自由記入。お客様にも表示）・使用資材・時間・メモ（スタッフ向け）・施術前後の写真。写真は非公開の場所に保存し、ログインした管理者と本人のお客様だけが見られる（ローカル／S3）。

### お客様向け：オンライン予約（`/book`）

- メニューを選ぶと、営業時間・既存の予約・直前の受付制限（60分前まで）・予約可能期間（60日先まで）から、予約できる枠を計算して表（○／×）で表示。
- 表の日時を選んで予約すると確定。確認メールを送信。
- **登録済みのお客様**は、かんたんログイン（電話番号＋生年月日）をしてから予約する。名前などの入力は不要。
- **はじめてのお客様**は、名前・電話番号・メール（必須）と生年月日（任意。月日がカルテ番号になる）を入力する。入力したメールに届く6桁の確認コードを入れると、顧客と予約ができる（本人のアドレスか確かめるまで登録しないので、他人がアドレスを先に登録できない）。登録済みの電話番号なら、ログインを案内する。
- 予約のあと、はじめてのお客様には**事前カウンセリング**（お悩みのチェックと自由記入）を案内。入力内容は予約一覧・顧客詳細に表示され、対応記録を作るときに最初から入る。

### お客様向け：かんたんログインと利用履歴（`/my`）

- **かんたんログイン**（電話番号＋生年月日）：登録済みのお客様が予約するときに使う。生年月日が未登録の方は、登録メールに届くコードで本人と確認してから登録できる（`/my/birthday`）。
- **利用履歴**（さらに、登録メールに届く6桁の確認コード）：これからの予約、来店の記録（日付・メニュー・カウンセリング・施術前後の写真）、過去の予約、AI相談の内容を表示。スタッフ向けのメモと使用資材は表示しない。
- 確認コードは10分で無効、5回まちがえると無効、1回使うと無効。履歴を見られるのは確認から30分まで。
- **LINE 連携**：利用履歴ページの「LINE と連携する」から LINE ログインで許可すると、お客様の LINE ユーザーIDを保存し、リマインドを公式アカウントから LINE で送る（送れないときはメール）。いつでも解除できる。LINE ログインと Messaging API のチャネルは、LINE Developers の同じプロバイダーに作る（`.env` の `LINE_*`。未設定なら連携ボタンを出さず、メールだけで送る）。
- 確認コードは、お店で登録した1つ目のメールアドレスにだけ送る（ログイン中の予約で入力されたアドレスは2つ目に入れ、コードの送り先にしない）。

### AI提案機能（お客様向け、ログイン不要）

- お客様が髪や頭皮の悩みを書くと、AIが質問を重ねながら絞り込み、登録済みメニューから1つを提案。「このメニューで予約に進む」で、そのメニューを選んだ状態の予約画面へ移る。
- 管理画面「AI提案結果」で、提案メニュー・予約の有無・会話内容を確認できる。AI相談のあと同じブラウザで予約すると、その相談が顧客に紐づき、顧客詳細にも表示される。
- 会話は `ai_sessions` / `ai_messages` に保存。1回目は必ず質問、最大4回で必ず提案して終える（`AI_MAX_TURNS`）。
- AIに渡す知識は、メニュー管理の「説明」と、管理画面「AI設定」の「お店の判断基準」。一覧にないメニューは作らず、頭皮の症状は断定せず専門医をすすめる。
- AI API は Gemini（`gemini-3.1-flash-lite`）。複数モデルを実測し、速さ（約1〜2秒）と答えの質で選定。呼び出しは `app/Services/Ai/MenuAdvisor.php` に集約し、他のAPIへ差し替えられる構成。混雑・時間切れは1回だけ再試行（待ち時間は1回8秒まで、`AI_TIMEOUT`）。1日の利用回数に、全体（`AI_DAILY_LIMIT`）とIPアドレスごと（`AI_IP_DAILY_LIMIT`）の上限。
- 相談画面に「外部のAIサービス（Google Gemini）に送信される」ことを表示。

### プライバシーポリシー（`/privacy`）

- 集める情報・利用目的・外部サービス（Gemini・メール・LINE）への送信・保存期間・問い合わせ先を表示。お客様向けの全ページの下と、予約・かんたんログイン・事前カウンセリング・AI相談のフォームからリンクしている。
- お店の名前は `APP_NAME`、問い合わせ先は `.env` の `SHOP_CONTACT` から表示する（コードには書かない）。
- 点検用コマンド `php artisan ai:eval` で、よくある相談12件（`database/ai-eval-cases.txt`）への提案を一覧にし、判断基準を直すたびに比較できる。

## 動かし方（ローカル）

```sh
git clone https://github.com/tgcore-build/suzuki-reservation-system.git
cd suzuki-reservation-system
cp .env.example .env        # DB を MySQL に切り替える（下の「.env の主な設定」を参照）
docker compose up -d --build
composer install
docker compose exec app php artisan key:generate
docker compose exec app php artisan migrate --seed
docker compose exec app php artisan db:seed --class=DemoSeeder   # デモ用データ（任意）
npm install && npm run dev  # 別のターミナルで起動したままにする
```

ブラウザで `http://localhost:8000` を開きます。管理画面のログインは `/login`、お客様向けの予約画面は `/book` です。`php artisan migrate --seed` で作られるテスト用ユーザー（`test@example.com`）は、ローカル開発専用です。

| 項目 | 例 | 説明 |

| `MAIL_MAILER` | `log` | ローカルでは、メールを送らずログに書き出す。本番は SMTP 等に切り替え |

| `PHOTO_DISK` | `local` | 対応記録の写真の保存先（どちらも非公開）。ローカルは `local`（ログインした管理者・本人のお客様だけが見られるURLで表示）、本番は `s3`（30分の一時URLで表示）。以前 `public` に保存した写真は `php artisan photos:move-to-private` で移す |
| `GEMINI_API_KEY` | （各自で取得） | AI提案機能の APIキー。Google AI Studio で発行 |
| `GEMINI_MODEL` | `gemini-3.1-flash-lite` | AI提案機能で使うモデル |

### リマインドメール

```sh
docker compose exec app php artisan reminders:send
```

「明日の確定済みの予約で、メールアドレスがあり、まだ送っていないもの」に送信し、送信日時を記録します（二重送信しません）。毎日18:00に自動実行する設定が `routes/console.php` にあります。本番では、スケジューラ（`php artisan schedule:run` を毎分、または `schedule:work`）を動かす必要があります。

## 本番の手順（Render ＋ Aiven）

公開用のファイル：`render.yaml`（Render の設定）、`Dockerfile.render`（本番用のイメージ）、`docker/start.sh`（起動のたびに動く処理）、`.dockerignore`。

### 1. 準備するもの

| もの | 使いみち |
|---|---|
| Render のアカウント | アプリを動かす（無料プラン） |
| Aiven のアカウント | DB（無料の MySQL） |
| SMTP のメールサービス | 確認メール・リマインド・確認コードの送信 |
| S3 など、非公開のファイル置き場 | 施術写真（無料プランのサーバーは、再起動でファイルが消えるため） |
| （任意）Gemini の APIキー、LINE のチャネル | AI提案、LINE でのリマインド |

### 2. DB（Aiven）

1. Aiven で MySQL のサービス（無料プラン）を作る。
2. 接続情報（Host・Port・User・Password・Database）と、CA 証明書（`ca.pem`）を控える。

### 3. アプリ（Render）

1. 手元で `APP_KEY` を作る：`docker compose exec app php artisan key:generate --show`
2. Render の画面で「New → Blueprint」を選び、このリポジトリを選ぶ（`render.yaml` の内容で作られる）。
3. `sync: false` の値を入れる。主なものは次のとおり。
   - `APP_NAME`・`MAIL_FROM_NAME`：お店の名前（画面とメールの差出人に出る）
   - `APP_KEY`：1で作った値。`APP_URL`：`https://〜.onrender.com`
   - `DB_*`：2の接続情報。`DB_SSL_CA_CERT`：`ca.pem` の中身をそのまま貼る
   - `MAIL_*`：SMTP の設定。`MAIL_FROM_ADDRESS` は、そのサービスで送信できるアドレスにする
   - `AWS_*`：写真を置くバケット（非公開にする。表示は30分の一時URL）
   - `ADMIN_EMAIL`・`ADMIN_PASSWORD`（12文字以上）：最初の管理者
   - `SHOP_CONTACT`：プライバシーポリシーに出す問い合わせ先
4. デプロイすると、起動のたびに `docker/start.sh` が、設定のキャッシュ・マイグレーション・最初の管理者の作成（`AdminUserSeeder`）を行う。

### 4. 最初の管理者

- `ADMIN_EMAIL`・`ADMIN_PASSWORD` があり、その管理者がまだいないときだけ作る。すでにいれば、パスワードは変えない（管理画面で変えたパスワードが、再起動で戻らないように）。
- 最初にログインしたら、プロフィール画面でパスワードを変え、Render の `ADMIN_PASSWORD` は消してよい。
- ローカルでも `ADMIN_EMAIL`・`ADMIN_PASSWORD` を `.env` に書いて `php artisan db:seed --class=AdminUserSeeder` で作れる。

### 5. リマインドの自動送信

リマインドは `routes/console.php` のスケジュール（毎日18:00に `reminders:send`）で送る。スケジュールを動かすには、`php artisan schedule:run` を毎分動かす必要がある。方法は次のどれか。

| 方法 | 内容 | 注意 |
|---|---|---|
| A（設定済み） | `RUN_SCHEDULER=true` で、アプリのコンテナの中で `schedule:work` を動かす | 無料プランは、しばらく使われないとスリープするので、18:00 に止まっていると送られない |
| B（確実） | Render の Cron Job（有料）。`render.yaml` の下のほうの `# - type: cron` の部分の `#` を外し、同じ環境変数を設定する。毎日 9:00（UTC）＝日本時間18:00 に `reminders:send` を動かす | Render の料金は公式サイトで確認する |
| C | ほかのサーバーの cron に `* * * * * cd /アプリの場所 && php artisan schedule:run >> /dev/null 2>&1` を登録する | |

送れなかった予約は送信済みにしないので、もう一度 `php artisan reminders:send` を動かせば送り直せる。
