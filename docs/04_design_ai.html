Week19 設計書：AI提案機能（画面設計・DB設計・API設計）

作成日：2026年9月23日　対象：AI提案機能

この設計書は「AI提案機能 要件定義書」をもとに、画面設計・DB設計・API設計をまとめたもの。予約・顧客管理システムは別紙「Week19 設計書：予約・顧客管理システム」で扱う。

Figmaワイヤーフレーム： こちらのリンクから確認できます（左側のページ一覧の「AI提案機能」ページに本機能の5画面があります）

連携方針： 本機能は予約・顧客管理システムのテーブル・APIを一切変更しない。接続点はai_sessions.customer_idという緩い参照1本と、提案結果を顧客向けメニュー選択画面（本体システム設計書 No.13）に引き継ぐ導線1箇所だけ。これにより本機能は単独でも動作し、後から接続することも、切り離すこともできる。

1. 画面設計

1.1 画面一覧

No 画面名 対象 概要
1 AI提案チャット：開始画面 利用者 悩み・要望を入力する前の初期画面
2 AI提案チャット：会話中画面 利用者 AIと質問・回答を重ねながら絞り込んでいる状態
3 AI提案チャット：提案結果画面 利用者 最終的なおすすめメニューと理由を提示し、予約へ導く
4 提案結果一覧（管理者向け・任意） 管理者 過去の提案結果を確認する（Could have）
5 エラーページ 共通 404 / 500、およびAI API障害時のエラーメッセージ

同じ「AI提案チャット」画面を、会話の進行段階（開始・会話中・結果）で3枚に分けてワイヤーフレーム化している。実装上は1つの画面が状態によって表示を切り替える想定。

2. DB設計

2.1 エンティティ一覧

  • ai_sessions（AI提案セッション）
  • ai_messages（AI提案の会話履歴）

2.2 テーブル定義（全テーブル）

テーブル: ai_sessions（AI提案セッション）

カラム名 型 NULL デフォルト 説明
id BIGINT NO AUTO セッションID（PK）
customer_id BIGINT YES NULL 予約・顧客管理システムのcustomers.idへの緩い参照（未ログインでも利用可）
result_menu VARCHAR(100) YES NULL 最終提案メニュー（未完了はNULL）
status ENUM NO ‘in_progress’ 進行中／完了
created_at / updated_at TIMESTAMP NO CURRENT 作成・更新日時

【インデックス】PRIMARY KEY (id) ／ INDEX (customer_id) 【外部キー】なし（customer_idは緩い参照のみで、予約・顧客管理システム側のテーブルへの外部キー制約は張らない）

テーブル: ai_messages（AI提案の会話履歴）

カラム名 型 NULL デフォルト 説明
id BIGINT NO AUTO メッセージID（PK）
session_id BIGINT NO - セッションID（FK）
role ENUM NO - user／ai
content TEXT NO - 発言内容
created_at TIMESTAMP NO CURRENT 作成日時

【インデックス】PRIMARY KEY (id) ／ INDEX (session_id) 【外部キー】session_id REFERENCES ai_sessions(id) ON DELETE CASCADE

2.3 ER図

テキスト形式のER図

ai_sessions (1) ----< (N) ai_messages

ai_sessions.customer_idは、予約・顧客管理システムのcustomers.idへの緩い参照（外部キー制約なし）。上記のER図には含めず、他システムのテーブルとは直接結びつけない。

3. API設計

メソッド エンドポイント 概要
POST /api/ai/sessions AI提案セッション開始
POST /api/ai/sessions/{id}/messages メッセージ送信・AI応答取得
GET /api/ai/sessions/{id} セッション内容・提案結果の取得

3.1 API詳細仕様（代表例）

API: メッセージ送信・AI応答取得

【エンドポイント】
POST /api/ai/sessions/{id}/messages

【説明】
利用者のメッセージをAIに送信し、応答を取得します。

【認証】
不要（利用者は未ログインでも利用可能）

【リクエストボディ】
{
  "content": "髪の乾燥が気になります"
}

【バリデーション】
- content: 必須、1-500文字

【レスポンス例（200 OK）】
{
  "role": "ai",
  "content": "乾燥が気になるとのことですね。他に気になる点はありますか？",
  "is_final": false
}

【エラーレスポンス例（422 Unprocessable Entity）】
{
  "message": "入力内容に誤りがあります",
  "errors": {
    "content": ["メッセージを入力してください"]
  }
}

API: セッション内容・提案結果の取得

【エンドポイント】
GET /api/ai/sessions/{id}

【説明】
セッションの会話履歴と最終提案結果を取得します。

【認証】
不要

【レスポンス例（提案完了時 200 OK）】
{
  "id": 88,
  "status": "completed",
  "result_menu": "メニューA",
  "messages": [
    { "role": "user", "content": "髪の乾燥が気になります" },
    { "role": "ai", "content": "メニューAをおすすめします。理由は..." }
  ]
}

【エラーレスポンス例（404 Not Found）】
{
  "message": "指定されたセッションが見つかりません"
}

4. 工数見積もり

4.1 機能別工数表

機能 マイグレーション モデル コントローラー ビュー 合計
チャットUI - - 1h 4h 5h
AI API連携（1往復・フォーム形式） - - 3h 1h 4h
会話履歴の保持（複数ターン化） 1h 1h 4h 2h 8h
提案結果の保存（Could have） 1h 1h 2h 1h 5h
開発工数合計 約22h
バッファ（20〜30%） 約4〜7h
見積もり合計 約26〜29h

利用するAI APIの費用体系・レスポンス速度が未確定なため、動作確認や調整にかかる時間を見込んでバッファを乗せている。この約22h（バッファ込み約26〜29h）は、下記の通りWeek22〜24では消化せず、フェーズ2で着手する時間として見込んでおく。

4.2 スケジュール

【スコープの再確認（講師フィードバックを受けて）】
予約・顧客管理システムとAI提案機能を合わせた当初の見積もりが3週間に対して過大との
指摘を受けたため、Week22〜24ではAI提案機能の実装を見送る。
Must have機能＋顧客向けオンライン予約（空き状況カレンダー優先）を優先して
「動くところまで」完成させることを最優先とする。

AI提案機能は設計（本ドキュメント）を確定させた状態でフェーズ2（Week24以降）に先送りする。
フェーズ2着手時の進め方は以下の2段階アプローチのまま変更しない：

第1段階：AI APIを選定し、1往復（フォーム形式）で最小実装
  → マイルストーン：悩みを送信すると提案が1回で返ってくる

第2段階：余裕があれば、ai_sessions／ai_messagesで会話履歴を持たせ、
         複数ターンのチャット形式に拡張
  → マイルストーン：会話しながら絞り込める
