Week21：タスク分解（GitHub Issues用）

作成日：2026年9月29日（2026年9月30日 スコープ見直し）　対象：予約・顧客管理システム＋AI提案機能（総合プロジェクト）

この文書は、Week19設計書「4.1 機能別工数表」とWeek20のスプリント計画をもとに、各機能をGitHub Issuesにそのまま登録できる形に分解したもの。下の各ブロックをコピーして、GitHubリポジトリのIssueとして1つずつ登録する。

スコープの再確認（講師フィードバックを受けて）： 予約・顧客管理システムとAI提案機能を合わせた当初の見積もり工数が3週間に対して過大との指摘を受けた。Week22〜24ではMust have機能＋顧客向けオンライン予約（空き状況カレンダー優先）を「動くところまで」完成させることを優先し、顧客向け利用履歴ページ（Issue 11）とAI提案機能一式（Issue 12〜15）はフェーズ2バックログとして切り出した。Issue 1〜10・16がWeek22〜24で実際に着手するタスク、Issue 11〜15はフェーズ2（Week24以降）のバックログとして登録しておく。

【ラベルの使い方】enhancementは新機能、setupは環境構築等の準備作業、phase2-backlogはWeek22〜24では着手しないフェーズ2の作業に付ける。Week22〜24のラベルで、どの週に着手する想定かを示す。

## 概要

- [ ] テストコード作成（PHPUnit：ログイン成功・失敗・未ログイン時のリダイレクト）（1h）

4時間（開発3h＋テスト1h）

## 優先度

ラベル: enhancement, Week22

Issue 7：自動リマインドメール送信

タイトル: [機能] 自動リマインドメール送信機能の実装

## 概要
来店予定の前日に、予約時に入力されたメールアドレス宛へリマインドメールを自動送信する。来店忘れによる機会損失を減らすため。メールアドレスが無い顧客は送信対象外とし、ログに残す。

## タスク
- [ ] reminder_logsテーブルのマイグレーション作成（1h）
- [ ] ReminderLogモデル作成（1h）
- [ ] バッチ処理（Laravel Scheduler）・メール送信（Laravel Mail）（8h）
- [ ] 送信ログ確認画面（2h）
- [ ] テストコード作成（PHPUnit：送信対象の抽出・Mail::fakeでの送信確認・メール未登録の除外）（3h）

## 見積もり
15時間（開発12h＋テスト3h）

## 優先度
Must have

ラベル: enhancement, Week23

## 備考
Week22序盤に、メール配信サービス（SMTPまたは配信API）の候補を決め、最小構成（1通送るだけ）の疎通確認を先に済ませておく。本番でのスケジューラの定期実行（Cron）設定はIssue 16のデプロイ時に行う。

Issue 8：既存ソフト連携（CSV取込）

タイトル: [機能] 既存予約管理ソフトとのデータ連携（CSV取込）

## 概要
既存の予約管理ソフトからエクスポートしたCSVを取り込み、同じ顧客情報を二重入力する手間をなくす。API連携は、既存ソフト側が対応している場合のみ行う（Could have）。

## タスク
- [ ] 既存ソフトのAPI・CSVエクスポート対応状況の調査（別途・Week22序盤に実施）
- [ ] 取込時の重複判定（external_idと電話番号）の実装（1h）
- [ ] コントローラー：CSV取込・重複チェック・結果ログ記録（6h）
- [ ] 取込画面・実行結果確認画面（2h）
- [ ] テストコード作成（PHPUnit：正常なCSV・重複データ・不正なCSV）（2h）

## 見積もり
11時間（開発9h＋テスト2h）＋調査時間別途

## 優先度
Must have（CSV取込）／Could have（API連携）

ラベル: enhancement, Week23

## 備考
CSV取込をMust have、API連携をCould haveとする。API連携は、調査の結果、既存ソフトが対応しており時間に余裕がある場合のみ着手する（目安：開発5h＋テスト2h）。Week22序盤に必ず仕様確認を行う。
